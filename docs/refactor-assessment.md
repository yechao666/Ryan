# Ryan 概念重构评估

分支：`refactor/employee-agent-workspace`

## 1. 现有设计的主要冗余与不合理点

### 1.1 员工、账号、身份混在一起

旧模型把 `Person`、登录账号、OIDC 身份和企业微信身份都称为“人员/账号”，管理员无法一眼确认某个员工是否已经绑定企业微信。

目标：

```text
员工（Employee） = 平台账户
├── 本地密码 / 组织认证
└── 企业微信身份（可选，但推荐）
```

### 1.2 智能体的“类型/接入方式/执行资源”混在一起

旧页面同时存在：

- 智能体类型：DSH / Claude
- 接入方式：本机 / 远端
- 主机、版本、插件版本、心跳、状态
- 没有能力标签

这导致“某个 Linux 主机上的测试智能体”无法表达成资源属性，只能靠名称暗示。

目标：

```text
智能体资源 = 主机 + 运行时类型 + 能力标签 + 状态 + token
```

能力标签例如 `linux`、`build`、`test`，用于说明它能承担什么工作。

### 1.3 项目上下文来源过多且边界不清

当前同时存在：

- 项目提示词
- 项目背景条目
- 提示卡
- 项目记忆
- 项目记录
- 任务内容

它们都会注入或影响任务，但没有明确层级，容易出现重复、互相冲突或上下文过长。

目标层级：

```text
项目提示词       短、稳定、最高优先级
项目背景条目     仓库、环境、基本要求和约定
提示卡           可复用的工作流/标准，按任务或自动注入
项目记忆         任务执行后沉淀的知识
项目记录         决策、风险、验收等过程事实
任务内容         本次任务的具体要求
```

### 1.4 任务接力有两套实现

之前增加了结构化的“接手人/接力卡/通知人”字段，后来又加入了自然语言 `@` 接力，两者重复。

已处理：

- 移除结构化接力字段和 UI；
- 保留自然语言 `@` 作为唯一的接力表达；
- 接力任务由提示词中的 `@` 语义驱动。

示例：

```text
开发完成后，请 @本机 DSH 服务 完成测试。
```

### 1.5 项目与工作区关系模糊

旧系统既有项目工作区，又有每个智能体的 workspace，但 UI 没有把“共享信息”和“本机执行现场”区分开。

目标：

```text
项目 = 跨智能体共享信息区
     背景 / 提示卡 / 记忆 / 记录 / 任务 / 复盘

智能体工作区 = 该智能体本机执行现场
     仓库文件 / 构建产物 / 本地日志
```

跨主机协作不要求共享文件系统，而是共享项目信息和任务交接。

### 1.6 事件模型重叠

当前同时存在：

- `task_events`
- `runtime_events`
- `activity_events`
- `task_notifications`

它们服务不同读者：

- runtime events：智能体运行细节
- task events：任务生命周期
- activity：项目活动流
- notifications：个人提醒

短期保留分层，但文档和 UI 应明确用途，避免把同一个事件重复展示成“进展”。

## 2. 目标模型

```text
员工账号 ──< 企业微信身份
   │
   ├── 创建/负责 ── 项目 ── 跨智能体共享信息区
   │                  │
   │                  └── 任务 ── @员工 通知 / @智能体 执行或接力
   │
   └── 调度 ──────── 智能体资源 ── 本机 / 远端主机
                          │  能力：linux / build / test
                          └── 项目工作区
```

## 3. 本轮已落地

- 账号管理增加员工语义、企业微信绑定列和筛选。
- 智能体增加能力标签，创建/编辑/列表展示。
- 项目概览增加共享信息区。
- 项目智能体页说明“共享上下文 + 各自工作区”。
- 新建统一的 `buildProjectBrief` 项目执行简报，集中组织项目提示词与背景，并限制最大字符数。
- 移除结构化接力字段，自然语言 `@` 作为唯一接力入口。
- 任务内容、提示卡、项目背景、项目提示词、自动化提示词支持 Markdown 形式的 `@` 提及。
- 任务提及、完成和接力接入站内通知。
- 文档补充员工/智能体/项目/任务/上下文层级。

## 4. 后续可继续重构

以下不作为本轮完成项：

1. **能力路由**：目前 `@智能体` 能指定资源，但普通调度尚未按能力标签自动路由。
2. **跨主机产物共享**：当前只共享项目信息，不共享各智能体本机文件；如需共享产物，应引入项目级 artifact 存储，而不是同步工作区。
3. **上下文预算与压缩**：目前限制 16k 字符，后续应按模型上下文窗口做分层摘要。
4. **领域命名**：内部仍保留 `DshInstance`、`serviceIds` 等历史命名，API 兼容期后可迁移为 `Agent`、`agentIds`。
5. **事件模型统一**：活动流、任务事件、通知可进一步抽象为统一事件总线，按消费端投影。
